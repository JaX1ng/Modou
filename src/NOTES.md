# 墨斗 · 项目说明（给 Jack 和 Claude）

当前版本：**2.5.1**（`js/config.js` 里的 `VERSION`）。**版本号按改动大小走（2.5.1 起，Jack：别每次都加 0.1）**：大.中.小 —— **大**（3.0.0）玩法核心大改（多流派 / 多角色、规则重做）、存档或联机整个不兼容；**中**（2.6.0）加了新玩法、新模式、新系统，或者改了规则、数值（手感会变）；**小**（2.5.1）画面、动作、声音、界面、小选项、修 bug —— 一次改好几条也是小版本。联机照旧要两边版本号完全一样。

**一份代码、两个出口**（2.1 起）：网页版（GitHub Pages）和软件版（Electron 打包的 Windows 程序，上 Steam 用）。以后每次改游戏，两边一起更新 —— 游戏代码只有一份，软件版就是把同一份网页装进一个窗口（见下面「软件版 / Steam」）。

## 给 Claude：改代码的规矩

1. 先读这份 NOTES，再按「文件地图」只打开要改的那一两个文件，不要通读全部代码。
2. 用精确替换做局部修改，不整文件重写。
3. 战斗逻辑里**不能用随机数、时间、画面数据**（`Math.random`、`Date`、`performance.now`、`F.J` 骨骼坐标、`FX` / `QI`、镜头 `camX` / `camZ`），也别用 `Math.sin`、`Math.pow` 这类不同浏览器可能算得不一样的函数。联机靠「同样输入 → 同样结果」，这些东西只能用在特效、声音、AI、颜色、镜头、场景里。声音用自己的随机数 `srnd`（2.1，见 fx.js），特效、画面用 `rnd` / `vpick`（2.4 起也是自己的随机数 `vrnd`），别让它们吃掉 `Math.random`（电脑 AI 用 `Math.random` / `pick`，测试里给 AI 固定了种子 —— 以前改一下动作、多一粒尘，电脑就打得不一样）。2.4 的「拳脚停在对方身上」（`fitContact`）也只改骨骼 J，是画面。
4. **联机回滚（1.9.0）会存档 / 读档**：`game.js` 的 `saveState()` 自动存角色身上所有字段 + `GAME_KEYS` 里的回合流程字段。给角色加了**纯画面**字段（只给动画、特效用的）→ 加进 `SNAP_SKIP`；给 `game` 加了**影响胜负**的字段 → 加进 `GAME_KEYS`。角色字段里别放「别的对象的引用」（对手、招式定义以外的对象），存档只浅拷贝一层。tests.js 的「存档 / 读档」「回滚」测试会查出漏存。
5. 特效、声音一律走 `addFx` / `Sound.xxx()`（回滚重算时它们先攒着、算完只补放多出来的，见 `fx.js` 的 `FXREC`）；别在战斗逻辑里直接往 `FX` 里 push。
6. 改完打开 `tests.html`，全部打勾才算完；新加规则就在 `js/tests.js` 补一条测试。
7. 动了招式数值、加了新招，打开 `balance.html` 看一眼平衡报告（见下面「查平衡」）；加了新招也想想破招练习（`js/drills.js`）要不要加一课。
8. 按改动大小改版本号（大.中.小，见最上面），在下面「改动记录」加一行，再打包两个出口：`python build.py`（网页版）、`python build.py --desktop`（软件版，见「软件版 / Steam」）。
9. **软件版专属的东西**（窗口全屏、2.4 三种画面、退出游戏、Steam 成就……）只能放在 `if (Desk)` / `window.modouDesktop` 后面（ui.js「软件版」那一段），网页版必须照旧能玩；跟平台无关的改动两边自动一样。
10. 回复里写清楚改了哪些文件；Project 里的文件、GitHub 仓库也要同步更新（见「发布」）。

## 发布（网页版 + 软件版，2.1 起）

- **GitHub 仓库 JaX1ng/Modou**（Jack 装了 Claude 的 GitHub 应用，只给了这个仓库）：
  - 根目录 `index.html` = 打包好的网页版（2.4 起是 `dist/index.html` 复制过去：字体从仓库里的 `src/fonts/` 读，不再向 Google Fonts 要 —— 上不了谷歌的人以前会卡在白屏、字也不对）。GitHub Pages 从 main 分支根目录发布，网址 https://jax1ng.github.io/Modou/（M 大写）。
  - `src/` = 全部源码（就是这份 NOTES 所在的目录：index.html、js/、css/、tests、balance、build.py、desktop/）。
  - `.github/workflows/desktop.yml` = 软件版自动打包。
- **claude.ai「格斗游戏」Project**：`modou/` 下面是源码的文本文件（= 仓库的 `src/`，图标这类二进制文件只在仓库里），`.github/workflows/desktop.yml` 也存一份。两边要一样。
- **每次更新**：改源码 → tests.html 全过 → 改 `VERSION`、写改动记录 → `python build.py` → 把 `dist/index.html` 复制成仓库根目录 `index.html`（2.3 以前是 `dist/modou.html`）、把源码放进 `src/`（连同 `src/fonts/`） → 提交推送（网页版就更新了）→ 推一个和版本号一样的 tag（`git tag v2.1.0 && git push origin v2.1.0`）→ GitHub Actions 打出 Windows 包（还顺手打 Linux、macOS），自动建 Release → 上 Steam 时把 Release 里的 `Modou-版本-win-x64.zip` 用 SteamPipe 传上去（步骤见 `desktop/STEAM.md`）。
- tag 必须等于 `v` + `VERSION`，不一样 CI 直接报错。

## 核心机制速查

- 60 帧/秒定步长。所有时长单位是「帧」。
- **节奏（1.8.0）**：`TEMPO` 1.07 = 比 1.7.0 慢约 7%。招式表写基准帧数，`M()` 统一换算；跑速、跳跃速度除以 `TEMPO`、重力除以 `TEMPO²`。
- **打击节奏（1.9.3）**：`HIT_TEMPO` 1.05 —— 招式前摇 / 判定 / 后摇、硬直、各种窗口（`TF()` 算的帧数）再慢 5%；跑、跳的速度不变。
- **节奏（2.0）**：帧数分三种换算 ——
  - `TF()`（×TEMPO×HIT_TEMPO）：一般帧数、受击硬直 `stun`、格挡硬直 `bstun`、各种窗口。连招靠 `stun`，真连一个没断。
  - `TFO()`（再 ×`OPEN_TEMPO` 1.12）：**起手招**（`open: true`：短拳、下盘拳、重拳、托天掌、铁山靠、腿踢、擒拿、抄腿、空中三招）的前摇和后摇一起长一点（看得清，平等）。
  - `TFH()`（只 ×TEMPO）：**挨了打的后摇**：倒地躺多久、起身、拼招 / 推挡 / 卸力 / 爆气的硬直。
- 场地宽 `STAGE_W` 1600（墙在 64 / 1536）。规则里用的画面宽 `W` 还是 1200。
- **画面（2.0）**：逻辑画面宽高比跟着画布走；按 `devicePixelRatio` 画，太大封顶约 1000 万像素。
- 镜头：人机 / 联机 / 训练场放大到 `ZOOM` 1.76，跟着自己，对手出画时画面边上画箭头；双人对战两人都在画面里。
- 招式数据结构：`S` 前摇、`A` 判定帧、`R` 后摇、`dmg`、`reach`（两人中心距，像素）、`stun`、`bstun`、`kb`、`lunge:[起帧,止帧,前冲像素]`、`open` 起手招。`base` 是换算前的帧数。

### 动起来的背景（2.5.1，`js/stage.js` 的 `LIVE`）

Jack：每张图都来点动态内容，比如桃花园背后的鸟随机从地图左边飞到右边，鸟要缓扇动翅膀；别的图也加类似元素，尽量少重复；尽量都往一边飘，不要一会儿从左到右、一会儿从右到左；不要干预专心玩游戏的视觉判断。

- **朱日远山**：三缕白云从左往右慢慢飘（5~10 像素/秒），飘出右边就从左边再进来一缕新的；四成从太阳前面过，把太阳遮淡一点（`cloudSprite`：一团团比纸白一点的雾、上边鼓起来、两头拖成细丝，底下一层很淡的灰）。
- **松崖飞瀑**：瀑布里一道道水线往下流（白的、淡灰的，`streaks`），快到底下淡进雾里；底下水雾一团团腾起来、往右散开（`spray`）。
- **竹林夜月**：十来只萤火虫一闪一闪、慢慢往右飘、上下浮着（黄绿色，夜里的灰底上看得出来；以前中景里十几个不动的亮点去掉了）；场地两头顶天的竹子迎着风慢慢摇（`bambooSway`：总是往右偏、一阵一阵的，竹叶跟着）。
- **桃花园**：鸟（Jack 点名）—— 隔 8~20 秒从地图左边飞进来一群（一只、两只或三只），缓缓扇翅膀（0.95~1.35 秒扇一下，扇几下滑一会儿 `birdFlap`），身子一起一伏，飞到右边出去；同时最多两群（以前远景里三只不动的燕子去掉了）。几片花瓣翻着跟头往右飘、慢慢往下落（在人头顶上面那一截，飘一阵就淡掉）。
- **大漠孤烟**：烽火台的孤烟一团团往上升（二十来秒升到顶，越往上越宽越淡，到顶上被风带着往右偏一点）；风卷起一缕缕沙从沙丘上往右掠过去（`sandWisp`：淡、细，两三秒就散）。
- **练武场**：两面旗迎风飘（旗面每帧现画 `liveFlag`：波纹从旗杆往外、从上往下走，褶子有深浅，穗子跟着甩；颜色是罩过中景那层纸色以后的样子）。
- 不干扰打架：都在人身后（远景、中景、场地两头），颜色淡、动得慢；鸟飞在远山前面、人头顶上面，花瓣在人头顶上面那一截；没有东西从人前面过。
- 怎么做的：每张图 `live: { far(g, L, st, dt), mid(...) }`，在贴完远景 / 中景那一层之后、同一套坐标里现画（跟着视差挪）；`L.vis` 是这一层里看得见的那一段。`Stage.live` 是这张图的状态（换图才清空，窗口缩放重画背景不清空），`Stage.liveStep()` 是真实时间（一帧最多算 0.1 秒；暂停、慢镜头照样动；菜单背景里也动）。场地两头每帧现画的 `near(ctx, st)` 也拿得到时间。
- 只用自己的随机数 `LIVE_R`（不碰 `Math.random`、`vrnd`：电脑 AI、特效都不受影响）；系统设置了「减少动态效果」（`reduceMotion`）就不动（旗子照样画，静止的）。只是画面：不进战斗逻辑、不走联机（两边各看各的）。测试「2.5.1 动起来的背景」查：每张图跑 40 秒画面在变、往一边飘的都往右、没用 Math.random / vrnd、鸟会飞来而且在扇翅膀、dt = 0 不动、画了背景战斗状态一模一样。
- 加一张图的动态：在 `LIVE` 里加 `id: { far / mid }`，状态挂在 `st` 上（第一次用时建），往一边飘的都往右（测试会查 `st` 里 birds / clouds / petals / flies / wisps / spray 的速度）。

### 颜色归属、画面插值（2.0.1）；头带、腰带（2.0.2）

- **谁的就是谁的颜色**（Jack：字幕、气、打击特效都要一眼看出是谁打的）。每个人的一套颜色都从身体色 `F.color` 算（`fx.js palOf`）：
  - `ink` 身体色：印章底板（白字）、伤害数字和飘字、冲击星的尖刺、墨点和地上的墨迹、地裂。
  - `fx` 打击色（同色提亮、提饱和）：打在对手身上的火花、集中线。墨这种没颜色的就是墨本身（提亮一点，深灰）。
  - `qi` 气（同色往淡里走，和身子的明暗对比 ≥ 2.6 倍，亮度封顶 0.36 免得纸上看不见）：身上的火、光、残影、拖尾线、扫痕、连招气浪、爆气圈 —— 从自己身上出来、贴着自己身子的都用淡的。
  - `core` 火花芯：再淡一层。
  - **`band`（2.0.2）头带、发带、腰带**：同一个颜色往亮里提一截（和身子的明暗对比 2.3 倍上下），饱和度略低一点像布。
  - 八个人的气、火花、带子两两颜色差 > 40（测试查）。
- **腰带（2.0.2）**：箍在腰上的一道带子（`drawBelt`：髋往上 9 像素、跟着上身斜，宽 5.2），和头带一样是一圈；发带只剩头上两条。
- 字幕归属：打出来的（加成「破招 ×1.2」、失衡、伤害、招式印章、擒住…）= 出招的人；挡住的「挡 -3」= 「挡」是挡的人、「-3」是打的人；势破、卸、霸体、化解、闪、挣脱 = 做到的那个人；「拼」「拆」= 两人各半；「压」= 压人的；连击数、气条、胜点 = 自己的；「某某 胜」= 赢的人。回合名、「战」、时间到、平局这种没有归属，墨色。飘字外面一圈淡淡的纸色描边。
- 特效分量：拼招两边一样多；压招压人的那边多、被压的那边少（`clashFx(…, 1, 0.35)`）；翻滚回去地上那个（赢的）多。
- 身上气旺的时候（连招的火、泼墨、爆气）身子外面换成一圈纸色的亮边（平时是淡墨影），同色的气里人照样看得清。
- **印章（2.0.2）**：所有招式印章按 `SEAL_K` 0.86 缩。
- **画面插值**（Jack：跑起来有虚影）：逻辑固定 60 帧/秒；主循环量屏幕刷新率（`rafAvg`）：60Hz 左右 → 对齐成正好一步、不插值；别的刷新率 → `RA` = 这一刻在两帧之间走到哪了，人、特效、气都在上一帧和这一帧之间插着画；KO 慢镜头时 60Hz 也插。上一帧的样子 `F.vp` 在 `SNAP_SKIP` 里。

## 查平衡（`balance.html`）

- 第一部分：在 6 个距离上，让两人从站定开始同时选一个计划（出招、挡、按时机挡 = 卸力、跳、冲刺、跑过去、看招再挡、闪身、边挡边退…），之后都按「好玩家」反应打完。收益 = 打掉的血 - 掉的血 + 击倒 ±6。对收益矩阵求均衡混合策略：某个选项在很多距离都占一大半 = 太强；「对随便出的对手平均赚多少」高的招最容易被滥用。
- 第二部分：电脑（困难，2.1 叫难）对电脑（困难）打 40 回合。第三部分：起身攻防。
- 这是模型，不是真人：反应、读招都理想化了，**没有墙**。数字只用来找「明显太强 / 太弱」。
- **2.2 的结果**（招式没动，只动了电脑）：第一、三部分和 2.1 一样；电脑（困难）对打：短拳 18%、重拳 9%、后手直拳 8%、腿踢 8%；击倒来自 冲天炮 21%、旋风腿 16%、短拳 14%、扫堂腿 10%、爆气 9%、踩腿 8%；挡后反击 200 次。
- **2.1 的结果**：
  - 对随便出的对手平均赚：千斤坠 8.4、泰山压顶 6.3（2.0.2 是 6.8）、飞踢 4.6（5.2）、重拳 3.4、跑过去短拳 3.3 —— 飞踢、泰山压顶削下来了，没有新的「一招鲜」。
  - 中立均衡：边挡边退平均占比 27%（2.0.2 是 21.5%），相距 120 和 210 各占一半上下。查过原因：是飞踢、泰山压顶变慢以后（Jack 要的），跳进来被往后挡着退的人罚得更狠（相距 95 飞踢打边挡边退从赚 5 变成亏 29），均衡就往「退着挡」偏了；边挡边退自己的收益没变（对谁都差不多是 0，只有跑过来擒拿、千斤坠、扫堂腿能赚它一点）。模型里没有墙，真打的时候退几步就到墙角，所以先不动它。要是真人对战觉得太龟，把 `BLOCK_WALK` 从 1.8 降到 1.5（实测平均占比回到 22%，相距 210 从 52% 降到 40%）。被挡住多收招（`BLOCK_PEN`）对这个模型没影响（实测去掉结果一模一样）。
  - 起身攻防：和以前一样（压的人平均赚 15.3，两种打法各一半）。
  - 电脑（难）对打：短拳 17%、后手直拳 9%、重拳 8%、腿踢 8%、擒拿 7%；击倒来自 冲天炮 23%、接腿摔 15%、旋风腿 11%、短拳 10%、扫堂腿 8%、踩腿 8%、爆气 8%；挡后反击 164 次（多收招以后打得出来了）。
- 2.0 的结果：中立均衡里平均占比 边挡边退 21.5%、看招再挡+对空 14.6%、站挡·第 11 帧按（卸力）11%、托天掌 7%、腿踢 7%；对随便出的对手：千斤坠 8.8、泰山压顶 6.5、飞踢 4.6、重拳 3.4；起身攻防压的人平均赚 15。
- 2.0.2 的结果：中立平均占比 边挡边退 21.5%、看招再挡+对空 15.9%、站挡·第 11 帧按（卸力）11.3%、托天掌 7.5%、腿踢 7.1%；没有哪个选项在哪个距离过半（最多：相距 145 托天掌 40%、相距 210 边挡边退 41%）。对随便出的对手：千斤坠 8.1、泰山压顶 6.8、飞踢 5.2、重拳 3.4、跑过去短拳 3.3。
- **动作衔接（2.1）**：每帧记两个人的骨骼，算每个关节的加速度，大的那些帧逐个看（一百多个场景：跳、跑、冲刺、各种招打空 / 打中 / 被挡、连招、擒拿后续、倒地起身、爆气、泼墨、卸力、推挡……，转身那一帧、打中停顿前后不算）。和 2.0.2 比没有变差的；找到的毛病是 IK 一帧翻边（见「核心机制速查」的 IK 弯向），修了以后 99% 分位从 65 降到 44，剩下最大的都是出拳出腿那一下本身（设计就是快）。

## 联机（P2P，1.9.0 重做）

- **房间码**：两边输入同一个房间码（去空格、英文不分大小写，最多 24 个字）就连上。找对方时经过公共信令（Trystero 的 Nostr 策略：往几个公共 Nostr 中继发加密的连接信息，`APP_ID` 'modou-ink-fight' 隔开别的应用，按 `APP_ID` 挑同一批中继 `SIGNAL_N` 8 个），连上以后两台电脑点对点直连，游戏数据不经过任何服务器。
  - 网址 `#房间码` 就是邀请链接（打开自动进房；刷新也还在这个房间）；房主填了中继的话，「复制邀请链接」会带上 `&r=压缩后的中继`。上次的房间码记在 localStorage `modou.room`。2.1 软件版复制出来的是网页版的网址（`WEB_URL`）。
  - 两人在 Trystero 的连接上各开两条约定好编号的通道（`negotiated`：66 可靠有序 ctl、67 不保证顺序不重传 in）。连上后两边互发 `hello`（版本号、加入方想要的颜色），收到对方的才算连上（hello 每半秒重发）。
  - 谁当房主：两边的 Trystero id 比大小，小的当房主。房主选色、选场景说了算、点开始。
  - 房间里已经有两个人：第三个人会收到「满了」（`busy`）。版本不同：两边都提示、自动退出房间。
  - 对局中掉线：等同一个人回来 `RECONNECT_WAIT` 20 秒，回来了接着打；对方关网页会先发 `bye`。
  - 想指定信令中继：localStorage `modou.signal` = `["wss://…"]`（改了要刷新）。
- **手动连接 · 局域网**（折起来的后备）：复制粘贴连接码 / 应答码，不经过任何服务器。2.3 起标明是两台设备在同一个局域网里（同一个 Wi-Fi / 路由器）时用；不在一个局域网的用房间码。
- **同步 = 回滚（rollback）**：两边各跑一份游戏，每帧只互传输入。本机输入只延后 1~3 帧；对方的输入没到就先猜往下算，每帧存档；猜错了读档用真的重算（`game.quiet`：重算时特效、声音先攒着，算完只补放多出来的）。对方落后超过 `MAX_PRED` 10 帧才停下来等。
  - 时间同步（GGPO 做法）：快一帧以上的那边每 6 帧停一帧。
  - 输入包是二进制：12 字节头 + 每帧 2 字节，只带对方还没确认收到的帧。
  - 每 `NET.HASH_EVERY` 帧互相比对 `stateHash()`，不一致时画面底部提示「联机不同步」。
- **声音、特效、气、颜色、镜头、场景都是各自电脑上算的，不走网络**（场景只在大厅里同步一次是哪张）。电脑 AI、破招练习不走联机（联机是两个人）。
- 有的网络不让两台设备直接通信（防火墙严、对称型 NAT，很多学校、公司、公共网络是这样）→ 用中继（TURN，联机面板「中继服务器」）。一边填就行。2.3 起界面上的说法都是这种通用的，不提具体哪种网络。
- 中继流量：每人每小时约 70 MB，Metered 免费版每月 20 GB。
- claude.ai 预览里沙盒不让直连，联机用网页版、软件版或下载的 html 文件。
- 页面切到后台时，ui.js 的 Worker 计时器继续推进 `Net.tick`（软件版切出去也照常跑：`backgroundThrottling: false`）。
- 测试：tests.js 里有存档 / 读档、回滚（模拟晚到、乱序、丢包）、补特效、输入包、邀请链接的测试。
