当前版本：**2.11.0**（`js/config.js` 里的 `VERSION`）。**2.9 / 2.10 为什么不是 3.0**：加第二个拳派、重做拳派按下面的规矩该算大版本，可 Godot 版已经在用 `3.0.0-alpha.N` 的号（见 `GODOT.md`）—— 网页版也叫 3.0.0 的话，两个不一样的游戏顶着同一个版本号（联机只认版本号，会以为能连），所以网页版记 2.x；等 Godot 版正式成了 3.0，网页版往后再接着走。**版本号按改动大小走（2.5.1 起，Jack：别每次都加 0.1）**：大.中.小 —— **大**（3.0.0）玩法核心大改（多流派 / 多角色、规则重做）、存档或联机整个不兼容；**中**（2.6.0）加了新玩法、新模式、新系统，或者改了规则、数值（手感会变）；**小**（2.5.1）画面、动作、声音、界面、小选项、修 bug —— 一次改好几条也是小版本。联机照旧要两边版本号完全一样。

**Godot 版（2026-10 起）**：Jack 定了把墨斗搬到 Godot、做成 2.5D（3D 模型），第一步用 Godot 原样还原 2.8.0（3.0.0）。计划、技术选择、分几步搬、规矩都在 **`GODOT.md`** —— 做 Godot 版的对话先读它。这份 NOTES 照旧是全部规则、数值的说明书，JS 代码是 Godot 版对照的标准答案；现在的网页版照常能玩、照常维护。

**一份代码、两个出口**（2.1 起）：网页版（GitHub Pages）和软件版（Electron 打包的 Windows 程序，上 Steam 用）。游戏代码只有一份，软件版就是把同一份网页装进一个窗口（见下面「软件版 / Steam」）。

**2.8 起（Jack：太耗额度）：平时只更新网页版，软件版先不动** —— 不跑 `python build.py --desktop`、不查软件版专属的东西、不碰 `desktop/`，也不在 GitHub 上打软件版的包。改的是共用的源码，下次打软件版自然带上。**等 Jack 说「更新软件版」「打包」再做**：`python build.py --desktop` 查一遍，然后在 GitHub Actions 手动跑 desktop（`gh workflow run desktop.yml -R JaX1ng/Modou --ref main`），把那次运行的网址给 Jack（Artifacts 里的 `modou-windows`，要登录他的 GitHub 才能下；不建 Release、不推 tag，他还没打算公开）。

## 给 Claude：改代码的规矩

1. 先读这份 NOTES，再按「文件地图」只打开要改的那一两个文件，不要通读全部代码。
2. 用精确替换做局部修改，不整文件重写。
3. 战斗逻辑里**不能用随机数、时间、画面数据**（`Math.random`、`Date`、`performance.now`、`F.J` 骨骼坐标、`FX` / `QI`、镜头 `camX` / `camZ`），也别用 `Math.sin`、`Math.pow` 这类不同浏览器可能算得不一样的函数。联机靠「同样输入 → 同样结果」，这些东西只能用在特效、声音、AI、颜色、镜头、场景里。声音用自己的随机数 `srnd`（2.1，见 fx.js），特效、画面用 `rnd` / `vpick`（2.4 起也是自己的随机数 `vrnd`），别让它们吃掉 `Math.random`（电脑 AI 用 `Math.random` / `pick`，测试里给 AI 固定了种子 —— 以前改一下动作、多一粒尘，电脑就打得不一样）。2.4 的「拳脚停在对方身上」（`fitContact`）也只改骨骼 J，是画面。
4. **联机回滚（1.9.0）会存档 / 读档**：`game.js` 的 `saveState()` 自动存角色身上所有字段 + `GAME_KEYS` 里的回合流程字段。给角色加了**纯画面**字段（只给动画、特效用的）→ 加进 `SNAP_SKIP`；给 `game` 加了**影响胜负**的字段 → 加进 `GAME_KEYS`。角色字段里别放「别的对象的引用」（对手、招式定义以外的对象），存档只浅拷贝一层。tests.js 的「存档 / 读档」「回滚」测试会查出漏存。
5. 特效、声音一律走 `addFx` / `Sound.xxx()`（回滚重算时它们先攒着、算完只补放多出来的，见 `fx.js` 的 `FXREC`）；别在战斗逻辑里直接往 `FX` 里 push。
6. 改完打开 `tests.html`，全部打勾才算完；新加规则就在 `js/tests.js` 补一条测试。
7. 动了招式数值、加了新招，打开 `balance.html` 看一眼平衡报告（见下面「查平衡」）；加了新招也想想破招练习（`js/drills.js`）要不要加一课。
8. 按改动大小改版本号（大.中.小，见最上面），在下面「改动记录」加一行，再打包网页版：`python build.py`。软件版（`python build.py --desktop`）只在 Jack 说要的时候打（2.8 起，见最上面）。
9. **软件版专属的东西**（窗口全屏、2.4 三种画面、退出游戏、Steam 成就……）只能放在 `if (Desk)` / `window.modouDesktop` 后面（ui.js「软件版」那一段），网页版必须照旧能玩；跟平台无关的改动两边自动一样。
10. 回复里写清楚改了哪些文件；Project 里的文件、GitHub 仓库也要同步更新（见「发布」）。

## 发布（网页版 + 软件版，2.1 起）

- **GitHub 仓库 JaX1ng/Modou**（Jack 装了 Claude 的 GitHub 应用，只给了这个仓库）：
  - 根目录 `index.html` = 打包好的网页版（2.4 起是 `dist/index.html` 复制过去：字体从仓库里的 `src/fonts/` 读，不再向 Google Fonts 要 —— 上不了谷歌的人以前会卡在白屏、字也不对）。GitHub Pages 从 main 分支根目录发布，网址 https://jax1ng.github.io/Modou/（M 大写）。
  - `src/` = 全部源码（就是这份 NOTES 所在的目录：index.html、js/、css/、tests、balance、build.py、desktop/）。
  - `.github/workflows/desktop.yml` = 软件版自动打包。
- **claude.ai「格斗游戏」Project**：`modou/` 下面是源码的文本文件（= 仓库的 `src/`，图标这类二进制文件只在仓库里），`.github/workflows/desktop.yml` 也存一份。两边要一样。
- **每次更新**：改源码 → tests.html 全过 → 改 `VERSION`、写改动记录 → `python build.py` → 把 `dist/index.html` 复制成仓库根目录 `index.html`（2.3 以前是 `dist/modou.html`）、把源码放进 `src/`（连同 `src/fonts/`） → 提交推送（网页版就更新了）→ 推一个和版本号一样的 tag（`git tag v2.1.0 && git push origin v2.1.0`）→ GitHub Actions 打出 Windows 包（还顺手打 Linux、macOS），自动建 Release → 上 Steam 时把 Release 里的 `Modou-版本-win-x64.zip` 用 SteamPipe 传上去（步骤见 `desktop/STEAM.md`）。
- tag 必须等于 `v` + `VERSION`，不一样 CI 直接报错。

## 核心机制速查

- **时间（2.6）**：逻辑一秒 240 步（`SIM_HZ`），一帧 = 4 步（`SUB`），一步 = 0.25 帧（`DT`）。时长的单位还是「帧」（1/60 秒），可以有零头（0.25 的倍数）。和屏幕刷新率无关：主循环按真实时间一步一步走，画面在两步之间插值（软件版 120 / 144 / 240Hz 都一样快、更细）。写法见下面「时间（2.6）」。（2.5 以前：60 帧/秒定步长，一帧一步。）
- **节奏（1.8.0）**：`TEMPO` 1.07 = 比 1.7.0 慢约 7%。招式表写基准帧数，`M()` 统一换算；跑速、跳跃速度除以 `TEMPO`、重力除以 `TEMPO²`。
- **打击节奏（1.9.3）**：`HIT_TEMPO` 1.05 —— 招式前摇 / 判定 / 后摇、硬直、各种窗口（`TF()` 算的帧数）再慢 5%；跑、跳的速度不变。
- **节奏（2.0）**：帧数分三种换算 ——
  - `TF()`（×TEMPO×HIT_TEMPO）：一般帧数、受击硬直 `stun`、格挡硬直 `bstun`、各种窗口。连招靠 `stun`，真连一个没断。
  - `TFO()`（再 ×`OPEN_TEMPO` 1.12）：**起手招**（`open: true`：短拳、下盘拳、重拳、托天掌、沉肩靠、腿踢、擒拿、抄腿、空中三招）的前摇和后摇一起长一点（看得清，平等）。
  - `TFH()`（只 ×TEMPO）：**挨了打的后摇**：倒地躺多久、起身、拼招 / 推挡 / 卸力 / 爆气的硬直。
- 场地宽 `STAGE_W` 1600（墙在 64 / 1536）。规则里用的画面宽 `W` 还是 1200。
- **画面（2.0）**：逻辑画面宽高比跟着画布走；按 `devicePixelRatio` 画，太大封顶约 1000 万像素。
- 镜头：人机 / 联机 / 训练场放大到 `ZOOM` 2.0（2.11 Jack：人物再大一点；2.6 ~ 2.10 是 1.86，2.0 ~ 2.5 是 1.76），跟着自己，对手出画时画面边上画箭头；双人对战、观战两人都在画面里。训练场镜头往上抬 `TRAIN_LIFT` 12（人往下挪，头和上面的面板之间留出空）。
- 招式数据结构：`S` 前摇、`A` 判定帧、`R` 后摇、`dmg`、`reach`（两人中心距，像素）、`stun`、`bstun`、`kb`、`lunge:[起帧,止帧,前冲像素]`、`open` 起手招。`base` 是换算前的帧数。
- `keys` 关键帧按**阶段**写 `[阶段, 姿势, 缓动]`：0 起手 → 1 出手 → 2 判定结束 → 3 收招完。script 动作写 0~1 表示整段进度。
- 姿势参数：`tor` 上身前倾、`head` 头低多少、`hy` 髋高、`dx` 髋前移、`fh/bh` 前/后手（拳心，相对两肩中间）、`ff/bf` 前/后脚（脚踝 x，离地多高）、`spin` 转身、`rot` 整个人转、`fe/be` 肘弯向（IK 的提示方向）、`air` 离地；**2.4：`tw` 拧腰（度：正 = 前手那边的肩膀往前送，出后手拳时负）、`fn/bn` 膝盖往前顶（1，默认）还是往后（-1）、`ft/bt` 脚尖往上勾（度）**；**2.5：`fo/bo` 膝盖往侧面（z）摆出去多少度** —— 膝盖绕「大腿根 → 脚踝」那条线往这条腿自己那一侧转（前腿往镜头这边、后腿往里），脚踝不动，脚尖跟着朝侧面；侧面看这条腿是缩短的。
- **IK 弯向（2.1，查动作衔接时发现的）**：肘、膝有两种弯法，以前每帧按提示硬挑，手走到肩膀上方、起跳、落地、被打倒摔下去时，提示一过线整条胳膊一帧翻到另一边（出短拳时后手肘最明显）。现在 `fk()` 记着上一帧弯在哪边（`ikS`），要换边就每帧最多挪 `IK_FLIP` 0.4（5 帧挪过去，肘从这边经过「对着镜头」移到那边），一直弯在同一边时和以前一模一样。只是画面。
- **站姿（2.4，参考图；2.5 照参考图第二张再调）**：身子微微往前（tor 6），后手拳护在下巴前，前手大臂往下垂、小臂往上立、拳在胸口前（比参考图收短、往里收）；两腿前后岔开（2.5 收近一点：前脚 24、后脚 -29），后腿差不多直、前腿膝盖微屈，髋高 73。出招的底子 `BASE` 跟着：髋 71、两脚 25 / -30。（2.1 是前手往前举、后手在腰带上面）
- **跳（2.1，Jack 的参考图）**：两条腿并着 —— 膝盖往前上提、小腿往后下收、脚在屁股底下（后腿不往后张开），两手往下垂、不往外张。最高约 94、空中约 31 帧；站着按方向跳约 175，跑起来跳约 240。
- 空中招：出手往前下方倾，判定持续到快落地；前摇没出完就落地 = 落地后在地上出。每跳一招。**2.1 飞踢前摇 9、判定 13、后摇 9；坠山击前摇 10、判定 11、后摇 10（基准帧，以前 6/12/7、7/10/8）**。
- **朝向（1.9.0 定的规矩，1.9.4 重做了「出招朝哪边」，2.0.2 修了坠山 / 空中招在头顶上时的判断）**：
  - 按着方向不出招 = 跑，马上朝那边（没有后退，不会被吸回去）。2.0 例外：按着挡 + 方向 = 边挡边走，一直面朝对手。
  - 不按左右（站着、蹲着）、格挡、挡住的硬直里：一律自动面向对手（`autoFace`，对手在身后超过 `FACE_HYST` 6 像素才转）。**2.0.2 例外：挨了回身肘踉跄的那几帧不转（背对着）**，踉跄完照常吸附。
  - 出招：对手在 `ASSIST_R` 170 以内一律朝能打中对手的那边打；更远才照按的方向打。例外：面前有人时按住后 + 拿 = 过肩摔。
  - `aimSide`：按的那一帧把两人接下来到判定结束的几帧推演一遍（自己的前冲、跑跳惯性、冲刺；对手的落点、起跳、滑动、推挤），朝打中帧多的那边；一样多就看「要是不出这一招，判定那一刻对手在我哪边」—— 到了身后 3 × `FACE_HYST` 以外才转。对手在地上跑 / 冲刺穿过来不算（那是他躲开了）。
  - **2.0.2（Jack：坠山在头顶上，底下的人还没等它到身后就往身后打，打空）**：以前把对手在空中当成「照惯性一直飞」，坠山其实在高处悬着、出脚那一帧重新瞄准、直着往下踩到人身上，推出来却是「飞过我、落到我身后」，招慢一点就转身往后打。现在照 update 推：坠山前摇里重力减半、横着匀速飘，出脚那一帧按我在哪重新瞄（和 `aimDive` 一样）；空中按着方向会加速；被顶回去翻跟头横着匀速飞；**他空中的招（坠山、飞踢、空中挥拳、坠山击）在判定帧里够到我了就停在那儿**（我先挨这一下，不会再飞过我；我这一招有无敌、托天掌对空无敌、蹲着躲飞踢时不算）；一样多时看「不出这一招时」对手在哪边。实测（坠山各种时机、底下按七种招，2520 次）：转身时它还在面前 33 → 0，选错边 33 → 4；普通跳着出飞踢 / 空中挥拳从头顶过来：转身打空时它还在面前 11 → 3。
  - 前冲不冲过人（1.9.4 `lungeStop`）。
  - **冲刺里回身出招（2.0）**：冲过了对手再回身打 —— 人还被冲刺带着往原来的方向滑（`DASH_TURN_KV` 4，滑二十来像素），也不带冲势（冲势只给往冲刺方向打的那一招，`dashFace`）。`aimSide` 里也按这个算。
- **跑步（1.9.0 / 1.9.4）**：大步、有腾空、后腿往后踢高、前膝抬高，上身前倾；跑的时候小臂往前上方伸。跑着起跳两臂展翅。
- 推挤是软碰撞（`SOFT_PUSH`），跑着能挤过去换边；冲刺、闪身、空中、过肩摔、滚身起、翻滚时不推挤。
- 真连招判断：下一招 S' + 2 ≤ 上一下的硬直。tests.js 里「图例里列的连招都是真连」逐个验证。连击衰减让一套最多五下左右（连珠快拳那样）。
- 交手关系 `relation()`：先比主系（克 ±1），主系一样比起手（压 ±0.5），都一样 = 平。
- 结算顺序（`combat.js resolve`）：两边这一帧的擒拿/打击意图 → 抓空 → 拆投、接腿 / 抄腿、打击打断擒拿 → 闪身躲重拳 → 两边都打中 = `exchange`；只有一边打中时看 `TRADE_LEAD` / `BEAT_LEAD` → 否则 `applyHit`（卸力 → 格挡 → 霸体 → 打中……）。

### 时间（2.6，Jack：帧逻辑别和实际帧率绑在一起）

Jack（2.6）：所有的帧逻辑不要和实际帧率绑定（软件版可以有更高帧率），时间算得更细；前后摇再拉高一点 —— 主要是拳头在对方身上停留的时间长一点作为后摇，所有动作前摇再长一点点（5~10%）。

其实 2.0.1 起逻辑就不跟屏幕刷新率走了（一秒固定 60 步，画面插值），绑着的是「时间的格子」：一步就是一帧（1/60 秒），什么都只能按整帧发生。2.6 把格子切细到 1/4 帧：

- **一秒 240 步**（`SIM_HZ`），`step(inputs)` = 一帧 = `SUB` 4 次 `simTick()`。主循环（ui.js）、联机回滚（net.js）都按步走。时长照旧按「帧」写（`S`、`R`、`stun`、各种窗口），只是可以是 0.25 的倍数（`grid()` 取格子）。
- **整帧的时候和以前一模一样**：速度是「像素 / 帧」，每步走 × `DT`；以前每帧乘 f 的衰减（击退 0.82、空气阻力、发带……）每步乘 `rootDT(f)`（f 的四次方根），位移系数用 `damp(f)` 配好 —— 走满一帧位移、速度和以前一样；重力分步算准（`alt += vz·DT + g·GH; vz -= g·DT`），跳的高度、空中时间和以前一样（最高 93.7、蹲 3 帧 + 空中 31 帧）；平滑跟随（每帧走 k）换成每步 `lerpK(k)`。
- **比较时间的写法（向下取整：第 k 帧 = [k, k+1)）**：以前写 `t > X` 的现在写 `t >= X + 1`，`t <= X` → `t < X + 1`；`>=`、`<`、倒计时 `<= 0`、`=== X`（整数 X）不用改。计时一律 `t += DT`、`-= DT`（别再 `++` / `--`）。`attackStep` 先查后加：以前查的 `m.t` 现在是 `k = m.t + DT - 1`（这一步结束时所在的那一帧），事件（`evHit`、`evPush`……）照旧 `k === 第几帧`。
- **输入**：`step()` 里按住的键每一步都按着，新按的招放在这一帧的最后一步（和以前「这一帧按、这一帧开始」一样）；电脑（`Brain.tick`）、破招练习（`Drill.tick`）、AI 看的快照 `record()` 一帧一次（最后一步）。缓冲里存着的招能在帧中间接上（取消窗口按步查），所以连招能接在 1/4 帧上。
- **联机**：回滚按步存档、按步重算，帧号 = 步数；每 `SUB` 步发一包（一秒还是 60 包左右）；`MAX_PRED`、`HASH_EVERY`、输入延迟这些参数照旧按「帧」写，用的时候 × `SUB`。两边版本号必须一样（2.6 和 2.5 不能一起联机）。
- **前后摇（`ATK_TEMPO` 1.075，`TA()`）**：非 script 的招前摇 `S`、后摇 `R`、硬直 `stun` / `bstun` 再 ×1.075 取到 1/4 帧（前摇平均长 7.9%，最少 6.3%，推挡 2 → 2.25 是 12.5%）；前冲、无敌、霸体这些招式自己时间轴上的东西跟着拉长；判定 `A` 不变；势破、推挡、破绽、截住闪身这些「挨了打 / 被挡」的帧数跟着 ×1.075；卸力失衡 `PARRY_STUN` 不变（够长，反打照样接得上）。2.5 的帧数存在 `MOVES[k].pre26`。
- **拳头在对方身上多停一会儿**：顿帧 `HITSTOP` 0.85 → 1.15（短拳 3 → 4 帧、重拳 7 → 10、腿踢 6 → 8）；收招开头两成（`HOLD_R`）拳脚停在打出去的位置再往回收（moves.js `M()` 在关键帧 2 后面插一帧一样的）。打中后短拳伸着的时间 3 → 6 帧。
- 测试「2.6 时间」「2.6 前摇……」查这些；以后加东西：每帧的量 × `DT`、每帧的衰减换 `rootDT`、比较时间按上面的写法。

- 输入里：冲刺键是新按的第 6 个键（第 10 位），「这个人用冲刺键」是第 11 位（`DASH_KEY`，每帧都带着；联机时对面的模拟也知道这个人双击不冲）。电脑 AI 照旧用双击。触屏多一个「冲」按钮（两种都能用）。
- 教程、破招练习里写「双击 [前]」的地方，选了冲刺键就自动写成「按 [冲]」（`dashWords`）。
- **2.5.1 两种都用**（Jack：冲刺可以选双击和单键都启用）：`dashMode` 'both' —— 双击方向照样冲，冲刺键也能冲（按着挡 = 闪身）。输入里不带「用冲刺键」那一位（那一位的意思就是「双击方向不冲」），冲刺键按下照样是第 10 位，所以不多占位、联机两边照样对得上。键位面板三格（`data-dashm`）；教程里写成「双击 [前] 或按 [冲]」，键位表两样都显示。

### 倒地、起身、压起身（2.0）

- 顺序：躺着 → **起身** `GETUP` 14 帧（打不中、动不了，从躺着撑到蹲着；按住方向 = 滚身起，滚 `ROLL_DIST` 96）→ **起身硬直** `RISE` 10 帧（站起来那几帧：打得中、还动不了，按什么都没用）→ 能动。普通击倒躺 `LIE_HIT` 30（扫堂腿 28），接腿摔 `LIE_GROUND` 43 / `LIE_AIR` 81，倒栽葱 `LIE_CRASH` 56。
- `RISE` 的长短按 Jack 说的定：对面在你刚能挨打那一帧（起身硬直第 0 帧）出短拳（前摇 5）来得及打中；出腿踢（前摇 16）、重拳（14）来不及 —— 你先能挡（刚按的挡还带卸力）。慢招要提前出、算好时机（压起身）；压早了打在起身里（打不中）就空了。测试里查：`短拳前摇 + 1 ≤ RISE - 2`、`腿踢前摇 + 1 > RISE`。
- 起身攻防的博弈（平衡报告第三部分）：原地起 = 什么都压得住（这就是「倒地 = 起身后被动」）；往对手脚下滚到他身后 —— 看见了转身出拳还来得及；往后滚 —— 看见了再追就晚了，只能他一起身就猜着冲过去，猜错了冲过头、回身打够不着。所以压的人在「看清再打」和「猜他往后滚」之间混，起来的人在两种滚之间混，压的人平均还是赚（约 15 血），但没有哪一招必赚。
- 躺姿（Jack：身子、腿、头都躺在地上，可以穿地一点点；发带也落在地上；手放在身体两边）：`POSE.lie`（一条腿稍弯）和 `POSE.lieFlat`（两腿伸直）每次倒地换着来（`lieKind`，只是画面）。
- **2.7**：躺的时间都 ×0.9；滚身起往后滚短了（64），滚完站起来那几帧 `RISE_ROLL` 16 帧（原地起身照旧 10）—— 看见他滚了再打，短拳打得到、腿踢打不到。见上面「2.7」。

### 边挡边走、闪身、回身肘（2.0 / 2.0.2）

- **边挡边走**：按住挡 + 方向（不蹲）= 举着手慢慢走（`BLOCK_WALK` 约 1.7/帧，跑步起步是 3.9），前后都行，一直面朝对手，正面来的照样挡住。蹲挡不走。克它：擒拿（挡不住）、下段（站着挡）、它走得慢，跑过去就贴上了。
- **闪身（边挡边冲刺）**：按住挡、朝对手双击方向（格挡中、挡住的硬直里都行）—— 压低身子从对手身边钻到他身后（冲多远按对手在哪算：`SLIP_PAST` 62，最少 70、最多 150）。
- **2.0.2（Jack：闪身躲完对面就打背身，后摇还让对面先起手，反而亏）：闪身只躲得过重拳** —— 站着打的重系手上招（重拳、进步冲拳、劈山掌、盖步砸拳、沉肩靠、截击，`slipDodges`）。钻的那十来帧（`slipInv`）重拳打来 = 「闪」，**躲过了就在他身后自动回身一肘（回身肘 `slipElbow`：前摇 5、判定 3、后摇 12、伤害 8，钻到他身后 `SLIP_ELBOW_AT` 30 那么远、或者钻完了就出）**。回身肘打中：他被打得**背对着你踉跄**（`STAGGER` 36 帧：打得中、挡不了、动不了，这几帧不自动转身，动画 `STAGGER_KEYS`：先往后一仰、再往前踉跄几步），你先动约 21 帧，够接短拳、短拳、重（冲天炮）一整套；踉跄完照常吸附转身。字幕只出闪的人的（「闪」、回身肘的印章、伤害数字），挨肘的人不出字。
- 闪身躲不过的：短拳、腿、下段、对空、空中招、擒拿 —— 冲进去的时候挨打 = 「截住闪身」×1.3、硬直多 `SLIP_CAUGHT_STUN` 帧。钻空了（对面没出重拳）就只是换到他身后（第 `SLIP_CANCEL` 9 帧起能直接出招），没有加成。
- 按着挡往后双击、不按挡双击：还是普通冲刺。

### 浏览器（2.0.2 / 2.1）

- Jack（2.0.2）：鼠标侧键绑成招，一按浏览器就后退；空格误碰页面往下滚。

- **现在两派**：`trad`「传统格斗」（moves.js 最后的 `STYLES`）、`wc`「咏春拳」（wingchun.js 最后挂进 `STYLES`，见上面「2.10：咏春拳」）。`STYLE_IDS`（game.js）是有哪几派、谁先谁后，选拳派面板、电脑选「随机」、教程「通用」里的拳派表都照它来；教程的书在 `GUIDE_BOOKS` 里另排。

  - 开关：`parry: false`（刚按下挡不是卸力）、`blockHeavy`（挡住的硬直里按重出什么，`null` = 不出）、`blockWalk`（按着挡走多快）、`catchGuard`（2.11：挡住的硬直里按拳不是推挡，交给这一派的 `defend`）；
  - 动作台、测试用：`benchGroups` / `benchHit`。
- **每个人身上记着自己是哪一派**（`F.style`，默认 `STYLE_DEFAULT`；存档、联机回滚都带着）。出招、取消、变招、擒拿的伤害都查自己这一派（`this.moves` / `styleOf(this)`）；两个人的招撞在一起走 `clashRelation(A, B)`：同一派照这一派的 `relation`，不同派查 `MATCHUPS['甲|乙']`（反过来写的那一对自动取负号），**没写就报错**，不会悄悄套用某一派的规矩。
- **再加一派要做的**（2.10 做咏春拳就是照这个来的）：
  1. **先写设计稿**（像 `WINGCHUN.md`）：这一派在按键上和别的派哪里不一样 —— 不能只是换一套动作；它的资源、它的弱点、对面怎么打它。Jack 定了再做。

  3. **跨派**：每一对新旧拳派写 `MATCHUPS['旧|新']`，系别那一套共用，只写多出来的；撞上以后有自己说法的写在 `clash` 钩子里。
  4. **联机**：这一派新加的状态（像咏春拳的顺、拍子、搭手、扣手腕）要能存档读档（战斗字段浅拷贝；只给画面用的放 `SNAP_SKIP`），不能用 `Math.random` / 时间；测试做一遍中途存档再读档接着算一模一样。

## 查平衡（`balance.html`）

- 第一部分：在 6 个距离上，让两人从站定开始同时选一个计划（出招、挡、按时机挡 = 卸力、跳、冲刺、跑过去、看招再挡、闪身、边挡边退…），之后都按「好玩家」反应打完。收益 = 打掉的血 - 掉的血 + 击倒 ±6。对收益矩阵求均衡混合策略：某个选项在很多距离都占一大半 = 太强；「对随便出的对手平均赚多少」高的招最容易被滥用。
- 第二部分：电脑（困难，2.1 叫难）对电脑（困难）打 40 回合。第三部分：起身攻防。

## 联机（P2P，1.9.0 重做）

- **房间码**：两边输入同一个房间码（去空格、英文不分大小写，最多 24 个字）就连上。找对方时经过公共信令（Trystero 的 Nostr 策略：往几个公共 Nostr 中继发加密的连接信息，`APP_ID` 'modou-ink-fight' 隔开别的应用，按 `APP_ID` 挑同一批中继 `SIGNAL_N` 8 个），连上以后两台电脑点对点直连，游戏数据不经过任何服务器。
  - 网址 `#房间码` 就是邀请链接（打开自动进房；刷新也还在这个房间）；房主填了中继的话，「复制邀请链接」会带上 `&r=压缩后的中继`。上次的房间码记在 localStorage `modou.room`。2.1 软件版复制出来的是网页版的网址（`WEB_URL`）。
  - 两人在 Trystero 的连接上各开两条约定好编号的通道（`negotiated`：66 可靠有序 ctl、67 不保证顺序不重传 in）。连上后两边互发 `hello`（版本号、加入方想要的颜色），收到对方的才算连上（hello 每半秒重发）。
  - 谁当房主：两边的 Trystero id 比大小，小的当房主。房主选色、选场景说了算、点开始。
  - 房间里已经有两个人：第三个人会收到「满了」（`busy`）。版本不同：两边都提示、自动退出房间。
  - 对局中掉线：等同一个人回来 `RECONNECT_WAIT` 20 秒，回来了接着打；对方关网页会先发 `bye`。
  - 想指定信令中继：localStorage `modou.signal` = `["wss://…"]`（改了要刷新）。
- **手动连接 · 局域网**（折起来的后备）：复制粘贴连接码 / 应答码，不经过任何服务器。2.3 起标明是两台设备在同一个局域网里（同一个 Wi-Fi / 路由器）时用；不在一个局域网的用房间码。
- **同步 = 回滚（rollback）**：两边各跑一份游戏，只互传输入。本机输入只延后 1~3 帧；对方的输入没到就先猜往下算，每步存档；猜错了读档用真的重算（`game.quiet`：重算时特效、声音先攒着，算完只补放多出来的）。对方落后超过 `MAX_PRED` 10 帧才停下来等。**2.6 起按步算**（一秒 240 步，帧号 = 步数，延迟可以是零点几帧），一帧（`SUB` 步）发一包。
  - 时间同步（GGPO 做法）：快一帧以上的那边每 6 步停一步（2.5 以前是每 6 帧停一帧，比例一样）。
  - 输入包是二进制：12 字节头 + 每步 2 字节，只带对方还没确认收到的步（2.6 一包最多 `PKT_MAX` 192 步）。
  - 每 `NET.HASH_EVERY` 帧互相比对 `stateHash()`，不一致时画面底部提示「联机不同步」。
- **声音、特效、气、颜色、镜头、场景都是各自电脑上算的，不走网络**（场景只在大厅里同步一次是哪张）。电脑 AI、破招练习不走联机（联机是两个人）。
- 有的网络不让两台设备直接通信（防火墙严、对称型 NAT，很多学校、公司、公共网络是这样）→ 用中继（TURN，联机面板「中继服务器」）。一边填就行。2.3 起界面上的说法都是这种通用的，不提具体哪种网络。
- 中继流量：每人每小时约 70 MB（2.6 一包多带几步输入，大概多三成上下），Metered 免费版每月 20 GB。
- claude.ai 预览里沙盒不让直连，联机用网页版、软件版或下载的 html 文件。
- 页面切到后台时，ui.js 的 Worker 计时器继续推进 `Net.tick`（软件版切出去也照常跑：`backgroundThrottling: false`）。
- 测试：tests.js 里有存档 / 读档、回滚（模拟晚到、乱序、丢包）、补特效、输入包、邀请链接的测试。
